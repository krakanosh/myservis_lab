# INSTALL.md — инструкция по установке и запуску MyServis

## 1. Назначение

Эта инструкция описывает установку и запуск веб-сервиса MyServis в среде Windows с использованием WSL2, Ubuntu 22.04+ и Docker Desktop.

Проект разворачивается в каталоге:

```text
/opt/myservis
```

Веб-интерфейс доступен по адресу:

```text
http://localhost:8080
```

Сервис собирает информацию об использовании дискового пространства, сохраняет показатели в SQLite и отображает их через веб-интерфейс и API.

## 2. Требования

Перед началом работы необходимы:

- Windows 10 или Windows 11 с поддержкой WSL2.
- WSL2.
- Ubuntu 22.04 или новее.
- Docker Desktop.
- Включённая интеграция Docker Desktop с WSL2.
- Доступ к интернету для загрузки Docker-образов и зависимостей.

**Важно:** в этой инструкции Docker Engine внутри Ubuntu отдельно не устанавливается. Используется Docker Engine, предоставляемый Docker Desktop через интеграцию с WSL2. Установка второго экземпляра Docker Engine может привести к конфликтам.

## 3. Установка и настройка WSL2

### 3.1. Проверка WSL

Открой PowerShell от имени администратора и выполни:

```powershell
wsl --status
```

Если WSL ещё не установлен, выполни:

```powershell
wsl --install -d Ubuntu-22.04
```

После установки перезагрузи компьютер, если система этого потребует.

### 3.2. Проверка версии Ubuntu

В PowerShell выполни:

```powershell
wsl -l -v
```

В списке должна присутствовать Ubuntu, а в столбце VERSION должно быть значение `2`.

Если используется версия 1, переключи дистрибутив на WSL2:

```powershell
wsl --set-version Ubuntu-22.04 2
```

Обновить WSL можно командой:

```powershell
wsl --update
```

## 4. Установка и настройка Docker Desktop

### 4.1. Установка

Скачай Docker Desktop с официального сайта:

https://www.docker.com/products/docker-desktop/

Установи приложение, выбрав использование WSL2 вместо Hyper-V, если установщик предлагает такой выбор.

После установки запусти Docker Desktop и дождись полной загрузки Docker Engine.

### 4.2. Включение WSL2 Engine

Открой настройки Docker Desktop:

1. Перейди в Settings.
2. Открой раздел General.
3. Убедись, что включена опция **Use the WSL 2 based engine**.
4. Нажми Apply & Restart, если настройки изменялись.

### 4.3. Включение интеграции с Ubuntu

В настройках Docker Desktop:

1. Перейди в раздел Resources.
2. Открой WSL Integration.
3. Включи интеграцию с установленным дистрибутивом Ubuntu.
4. Нажми Apply & Restart.

## 5. Проверка Docker в Ubuntu

Запусти Ubuntu через меню Windows или командой:

```powershell
wsl -d Ubuntu-22.04
```

Проверь доступность Docker CLI:

```bash
docker --version
```

Проверь Docker Compose:

```bash
docker compose version
```

Проверь подключение к Docker Engine:

```bash
docker info
```

Команды должны выполняться без ошибок.

Если команда `curl` отсутствует, установи её:

```bash
sudo apt update
sudo apt install -y curl
```

Если Docker недоступен, проверь, что Docker Desktop запущен и интеграция с Ubuntu включена.

## 6. Получение генератора проекта

Скопируй файл `generate_project.sh` из Windows в домашний каталог Ubuntu.

Например, если файл находится в папке Downloads пользователя Windows:

```bash
cp /mnt/c/Users/<WINDOWS_USER>/Downloads/generate_project.sh ~/
```

Вместо `<WINDOWS_USER>` укажи имя своей учётной записи Windows.

Перейди в домашний каталог:

```bash
cd ~
```

Добавь разрешение на выполнение:

```bash
chmod +x generate_project.sh
```

Проверь синтаксис скрипта:

```bash
bash -n generate_project.sh
```

Если команда не вывела ошибок, синтаксис проверку прошёл.

## 7. Генерация проекта

Запусти генератор:

```bash
sudo bash ./generate_project.sh
```

Скрипт создаст проект в каталоге:

```text
/opt/myservis
```

После завершения перейди в каталог проекта:

```bash
cd /opt/myservis
```

Ожидаемая структура проекта:

```text
/opt/myservis/
├── app/
│   ├── app.py
│   ├── config.yaml
│   └── requirements.txt
├── data/
├── logs/
├── scripts/
│   ├── 01_prepare.sh
│   ├── 02_create_structure.sh
│   ├── 03_build_and_up.sh
│   ├── 04_info.sh
│   └── 05_check.sh
├── Dockerfile
├── compose.yaml
└── README.md
```

Фактическое содержимое отдельных файлов определяется генератором.

## 8. Развёртывание веб-сервиса

Скрипты необходимо выполнять последовательно из каталога `/opt/myservis`.

### 8.1. Подготовка окружения

```bash
sudo bash scripts/01_prepare.sh
```

Скрипт проверяет наличие необходимых инструментов и доступность Docker.

При использовании Docker Desktop отдельный Docker Engine внутри WSL не устанавливается.

Ожидаемый результат:

```text
[+] Linux/WSL, curl, Docker CLI, Docker daemon и Compose v2 доступны.
[+] Docker Engine внутри WSL не устанавливался: используется Docker Desktop.
```

### 8.2. Создание структуры каталогов

```bash
sudo bash scripts/02_create_structure.sh
```

Скрипт проверяет структуру проекта и подготавливает каталоги для хранения данных и логов.

Ожидаемый результат:

```text
[+] Структура проверена; каталоги data/ и logs/ готовы.
```

### 8.3. Сборка и запуск контейнера

```bash
sudo bash scripts/03_build_and_up.sh
```

Скрипт собирает Docker-образ и запускает контейнер через Docker Compose.

После успешного выполнения контейнер `myservis` должен быть запущен.

### 8.4. Получение информации о сервисе

```bash
bash scripts/04_info.sh
```

Скрипт выводит информацию о состоянии контейнера, сетевых настройках, порте и работе приложения.

### 8.5. Проверка работоспособности

```bash
bash scripts/05_check.sh
```

Скрипт проверяет:

- Доступность веб-страницы по HTTP.
- Состояние контейнера.
- Наличие записей в базе SQLite.
- Наличие файла журнала.

При успешном прохождении проверок появится сообщение:

```text
[+] Ожидание HTTP-сервиса (до 30 секунд)...
[+] HTTP GET /: 200
[+] Контейнер myservis: running
[+] SQLite: количество записей
[+] Лог: непустой
[+] OK — все проверки пройдены.
```

Количество записей в базе зависит от времени работы сервиса.

## 9. Проверка веб-интерфейса

Открой браузер Windows и перейди по адресу:

http://localhost:8080

Должна открыться главная страница веб-сервиса с информацией об использовании дискового пространства.

## 10. Проверка API

Сервис предоставляет два API-эндпоинта.

### 10.1. Текущие показатели

Выполни в терминале Ubuntu:

```bash
curl -i http://localhost:8080/api/current
```

Эндпоинт возвращает текущую информацию об использовании дискового пространства в формате JSON.

### 10.2. История показателей

```bash
curl -i http://localhost:8080/api/history
```

Эндпоинт возвращает историю собранных показателей в формате JSON.

## 11. Проверка состояния контейнера

Для просмотра запущенных контейнеров проекта выполни:

```bash
docker compose ps
```

Для просмотра журнала приложения:

```bash
docker compose logs
```

Для просмотра журнала в режиме реального времени:

```bash
docker compose logs -f
```

Чтобы выйти из режима просмотра журнала, нажми `Ctrl+C`. Это не останавливает контейнер.

## 12. Проверка базы данных и логов

Данные приложения хранятся в каталоге:

```text
/opt/myservis/data/
```

Основная база данных:

```text
/opt/myservis/data/metrics.db
```

Журнал приложения:

```text
/opt/myservis/logs/myservis.log
```

Проверить наличие файлов можно командой:

```bash
ls -lah data logs
```

Посмотреть последние записи журнала:

```bash
tail -n 20 logs/myservis.log
```

Проверить размер базы данных:

```bash
ls -lh data/metrics.db
```

## 13. Остановка и повторный запуск сервиса

Все команды управления Docker Compose необходимо выполнять из каталога `/opt/myservis`.

### 13.1. Остановка контейнера

```bash
docker compose stop
```

Команда останавливает контейнер, но не удаляет его.

### 13.2. Повторный запуск

```bash
docker compose start
```

### 13.3. Остановка с удалением контейнера

```bash
docker compose down
```

Команда останавливает и удаляет контейнер и сеть проекта.

Каталоги `data/` и `logs/` сохраняются, поскольку используются bind mounts.

**Не добавляй параметр `-v`, если необходимо сохранить данные проекта.**

### 13.4. Запуск после остановки

```bash
docker compose up -d
```

### 13.5. Пересборка и запуск

Если были изменены исходный код приложения или Dockerfile:

```bash
docker compose up -d --build
```

## 14. Возможные проблемы

### Docker: command not found

В Ubuntu не находится команда `docker`.

Что проверить:

1. Запущен ли Docker Desktop.
2. Включена ли интеграция с используемым дистрибутивом Ubuntu.
3. Перезапущен ли терминал Ubuntu после включения интеграции.

При необходимости выполни в PowerShell:

```powershell
wsl --shutdown
```

Затем снова запусти Ubuntu.

### Docker daemon недоступен

Если Docker CLI установлен, но команды сообщают об ошибке подключения к daemon:

1. Запусти Docker Desktop.
2. Дождись полной загрузки Docker Engine.
3. Проверь WSL Integration.
4. Повтори проверку:

```bash
docker info
```

### Docker Compose недоступен

Проверь версию Compose:

```bash
docker compose version
```

В этой инструкции используется команда `docker compose`, а не устаревшая отдельная команда `docker-compose`.

### Порт 8080 занят

Если контейнер не может запуститься из-за занятого порта, проверь, какой процесс использует порт:

```bash
sudo ss -ltnp | grep ':8080'
```

Останови конфликтующий процесс либо освободи порт, после чего повтори запуск:

```bash
docker compose up -d
```

### Веб-страница не открывается

Проверь состояние контейнера:

```bash
docker compose ps
```

Посмотри журнал:

```bash
docker compose logs --tail=100
```

Убедись, что приложение запущено и порт 8080 опубликован.

### Контейнер завершает работу

Посмотри журнал контейнера:

```bash
docker compose logs myservis
```

Проверь наличие ошибок в конфигурации и исходном коде приложения.

### В базе данных нет записей

Проверь, что контейнер запущен:

```bash
docker compose ps
```

Посмотри журнал приложения:

```bash
tail -n 50 logs/myservis.log
```

Убедись, что сервису хватает времени для первого сбора показателей. Интервал сбора задаётся в `app/config.yaml`.

```bash

bash -n generate_project.sh

# Генерация проекта
sudo bash ./generate_project.sh

# Переход в каталог проекта
cd /opt/myservis

# Подготовка окружения
sudo bash scripts/01_prepare.sh

# Создание структуры
sudo bash scripts/02_create_structure.sh

# Сборка и запуск
sudo bash scripts/03_build_and_up.sh

bash scripts/05_check.sh

docker compose ps
```

После успешного выполнения сервис будет доступен по адресу:

http://localhost:8080
