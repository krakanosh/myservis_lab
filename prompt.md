# Промпт для ИИ-ассистента

Создай один самодостаточный Bash-скрипт `generate_project.sh`, который автоматически разворачивает проект веб-сервиса мониторинга дискового пространства в Docker Compose.

## Среда и параметры
- Целевая ОС: Ubuntu 22.04+ в WSL2.
- Docker запускается через Docker Desktop в Windows с включённой интеграцией WSL для используемого дистрибутива Ubuntu. Не устанавливай второй Docker Engine внутрь WSL.
- Корневой каталог проекта: `/opt/myservis`.
- Имя Compose-сервиса и контейнера: `myservis`.
- Веб-фреймворк: Flask.
- Веб-порт: `8080` (доступен на хосте по `http://localhost:8080`).
- Хранилище метрик: SQLite.

## Требования к генератору
1. Выведи только один законченный Bash-скрипт `generate_project.sh`; не разделяй решение на несколько файлов.
2. Используй `#!/usr/bin/env bash` и `set -euo pipefail`.
3. Генератор должен быть идемпотентным: повторный запуск не должен приводить к ошибкам или дублированию структуры.
4. Создавай файлы через heredoc (`cat <<'EOF'`).
5. Создай проект в `/opt/myservis` со структурой:
   - `app/main.py`
   - `app/config.yaml`
   - `app/requirements.txt`
   - `app/Dockerfile`
   - `docker-compose.yml`
   - `scripts/01_prepare.sh`
   - `scripts/02_create_structure.sh`
   - `scripts/03_build_and_up.sh`
   - `scripts/04_info.sh`
   - `scripts/05_check.sh`
   - `README.md`
   - каталоги `data/` и `logs/`.
6. Корректно обработай права на `/opt`: если каталог недоступен для записи, запроси повышение привилегий через `sudo`, затем передай владение проектом текущему пользователю (или исходному пользователю при запуске через sudo).
7. Все пять вспомогательных скриптов должны иметь shebang `#!/usr/bin/env bash`, `set -euo pipefail`, быть идемпотентными и печатать понятные сообщения с префиксами `[+]`, `[!]`, `[x]`.
8. `01_prepare.sh`: проверь Linux/WSL2, Docker CLI, доступность демона Docker Desktop, Compose v2 и `curl`. Не устанавливай Docker Engine в WSL: если Docker Desktop/WSL integration не настроены, выведи точную инструкцию по включению интеграции и заверши работу с ошибкой.
9. `02_create_structure.sh`: проверь наличие обязательных файлов, создай `data/` и `logs/`, выставь права для текущего пользователя.
10. `03_build_and_up.sh`: собери образ и запусти сервис в фоне через `docker compose up -d --build`.
11. `04_info.sh`: выведи корень проекта, статус `docker compose ps`, последние 10 строк логов контейнера, количество записей SQLite и URL сервиса.
12. `05_check.sh`: дождись запуска сервиса (не более примерно 30 секунд), проверь состояние контейнера, HTTP 200 на `/`, наличие не менее одной записи в SQLite и непустой лог. При любой ошибке заверши скрипт с кодом 1; при успехе выведи итоговый OK.
13. Приложение должно быть на Python 3 + Flask. Фоновый поток с периодом `interval_sec` из YAML собирает статистику корневой файловой системы через `shutil.disk_usage("/")`, сохраняет её в SQLite `data/metrics.db`. Таблица `disk_stats`: `id`, `ts`, `total`, `used`, `free`, `percent`. Время — ISO 8601.
14. При превышении `threshold_percent` записывай WARNING в лог. Лог `logs/myservis.log` должен иметь формат `[YYYY-MM-DD HH:MM:SS] [LEVEL] message`.
15. GET `/` возвращает HTML-страницу с текущими показателями и последними 20 записями. GET `/api/current` возвращает актуальную метрику в JSON, GET `/api/history` — историю в JSON.
16. Корректно обрабатывай SIGTERM: останавливай фоновый поток без аварийного завершения.
17. `docker-compose.yml`: один сервис `myservis`, сборка из `./app`, проброс `8080:8080`, bind mounts `./data:/app/data` и `./logs:/app/logs`, `restart: unless-stopped`.
18. Dockerfile должен запускать Flask на `0.0.0.0:8080`.

В конце добавь краткую инструкцию запуска и проверки. Не утверждай, что контейнер реально запущен или проверен: генератор только создаёт проект.
