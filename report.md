# Отчёт по лабораторной работе

## Тема
Автоматизация развёртывания веб-сервиса в Docker Compose с помощью Bash-скрипта-генератора, полученного от ИИ-ассистента.

## Цель работы
Получить Bash-генератор, создающий структуру Flask-приложения мониторинга дискового пространства, конфигурацию Docker Compose и вспомогательные скрипты для подготовки среды, запуска, просмотра состояния и проверки сервиса.

## Исходный промпт
Полный промпт приведён в файле [`prompt.md`](prompt.md).

## Условия выполнения
- ОС: Ubuntu 22.04+ в WSL2.
- Docker: Docker Desktop в Windows с включённой WSL Integration.
- Каталог проекта: `/opt/myservis`.
- Сервис: `myservis`.
- Приложение: Python + Flask.
- База данных: SQLite.
- Порт: `8080`.

**Особенность среды:** Docker Engine не устанавливается повторно внутрь WSL. Скрипт `01_prepare.sh` проверяет доступность Docker Desktop через WSL integration. Это согласованная адаптация шага подготовки к фактически выбранной среде.

## Состав решения
- `generate_project.sh` — самодостаточный генератор файлов проекта.
- `app/main.py` — Flask-приложение и фоновый сборщик метрик.
- `app/config.yaml` — параметры сбора, порог предупреждения, пути БД и лога.
- `app/Dockerfile` — образ приложения.
- `docker-compose.yml` — запуск одного сервиса `myservis`.
- `scripts/01_prepare.sh` — проверка WSL/Docker Desktop/Compose/curl.
- `scripts/02_create_structure.sh` — проверка файлов и создание каталогов данных/логов.
- `scripts/03_build_and_up.sh` — сборка и запуск.
- `scripts/04_info.sh` — сводная информация, состояние, логи и количество метрик.
- `scripts/05_check.sh` — автоматические проверки.
- `README.md` — инструкция пользователя.

### Почему база данных хранится в подключённом каталоге?
SQLite-файл находится в `./data`, который подключён к `/app/data` через bind mount. Поэтому база остаётся на файловой системе проекта и не теряется при удалении или пересоздании контейнера. Аналогично сохраняются журналы в `./logs`.
